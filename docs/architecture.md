# 연주와 웹 호스트의 경계

제품 용어와 동작의 의미는 [용어집](../GLOSSARY.md)에 정리한다.
연주 순서, 브라우저 입력 수명, 비동기 로딩 수명은 각자 한 모듈이 책임진다.

| 모듈 | 책임 | 호출자가 알아야 할 경계 |
|---|---|---|
| `rive/performance.as` | 현·선택·안내·예시 연주의 호출 순서, 조작 소유자와 연주 상태 | 누르기·이동·놓기·중단과 버튼 명령을 받는다. 놓기의 물방울·음 결과와 시간 진행 중의 음을 반환한다. |
| `rive/main.as` | Rive 호스트, view model, 오디오, GPU 수면 | 외부 취소를 먼저 적용하고 연주 명령을 전달한다. 반환된 음을 보내고 상태를 view model에 반영한다. |
| `web/src/pointer-session.ts` | 네이티브 포인터 소유권과 안내 수명 | 입력 취소는 플레이어에 전달한다. Rive의 관측 상태는 그림에만 사용하며 소유자를 변경하지 않는다. |
| `web/src/drag-guide.ts` | 손 옆의 음높이·참고 길이 표시 | 포인터 위치와 관측 상태를 받아 그린다. 이벤트 리스너나 별도 입력 소유자를 두지 않는다. |
| `web/src/playback-session.ts` | 재생 의도, 로딩 완료·실패, 타이머와 정리 | 로더와 상태 알림을 받는다. 정리 뒤 도착한 플레이어는 재생하지 않고 즉시 해제한다. |
| `web/src/player.ts` | Rive 웹 런타임과의 연결 | view model, 재생·음량, 캔버스 크기와 리소스를 관리한다. 네이티브 포인터의 수명은 관리하지 않는다. |
| `web/src/main.ts` | DOM과 모듈 연결 | 사용자 명령을 전달하고 모듈 상태를 화면에 표시한다. |

## 연주 순서

`Performance`만 `Strings`, `Controls`, `Guide`, `Phrase`를 조합해 사용자 동작을 수행한다.
그리기와 튕기기는 먼저 현 상태를 바꾸고 안내에 결과를 전달한다. 버튼은 진행 중인
드래그와 예시 연주를 중단한 뒤 선택·생성·튕기기를 수행한다. 안내 테스트도 이 경로를
호출하므로 테스트 안에 별도 연주 순서를 복제하지 않는다.

물리 계산은 기존처럼 `Main.draw()`에서 현과 수면을 함께 진행한다. 프레임 지연의
최대 따라잡기 시간은 0.5초이고, `Phrase`의 장면 시계와 늦은 음 건너뛰기는 유지한다.
오디오와 GPU 초기화는 `Main`에 남으므로 연주 검사는 해당 호스트 없이 실행한다.

`Performance.release()`의 결과는 다음 `release()`까지 빌려 쓰는 값이다.
호출자는 `accepted`를 확인한 뒤 즉시 물방울과 음을 처리한다. `revision`은 선택·현 목록·
음 수·예시 연주 상태를 다시 게시할 때 사용하며, 드래그 미리보기와 커서는 별도로 게시한다.

## 입력과 재생의 수명

브라우저 입력과 Rive 관측은 서로 다른 시계로 도착한다. 앞선 놓기의 관측이 새 누르기보다
늦어져도 새 포인터를 버리지 않는다. 두 번째 손가락의 취소 역시 첫 손가락의 조작을
중단하지 않는다. 우클릭은 안내를 표시하지 않지만, Rive가 받는 입력이므로 취소 소유권은 유지한다.

화면 크기 변경은 현재 드래그 안내만 닫는다. 현을 놓거나 취소하지 않는다.
Escape, 도움말 열기, 일시정지, blur와 페이지 숨김은 조작을 중단한다.
직접 그린 현의 연속 음높이는 크기나 참고 화음 변경으로 다시 조율하지 않는다.

로딩 완료는 400ms의 장면 퇴장보다 먼저 입력을 연다. 준비가 10초를 넘으면 지연 안내를
알리며, 완료·실패·정리 시 관련 타이머를 취소한다. 움직임 줄이기는 최초 로딩을 미루고
설정 변경 시 일시정지하지만, 설정 해제만으로 자동 재개하지 않는다.
서비스 워커의 문서 교체를 기다릴 때는 로딩 장면을 유지하며, bfcache 보관은 해제로 취급하지 않는다.

## 검증 경계

- `rive/*_test.as`: 실제 `Performance`를 통해 입력 소유권·취소·안내 인계·예시 연주를 검사한다.
  현 물리·개별 제어·화음·스케줄러의 기존 검사는 유지한다.
- `web/tests/pointer-session.spec.ts`: 실제 모듈과 브라우저 이벤트를 사용해 늦은 관측,
  두 손가락, 우클릭, 리사이즈와 리스너 정리를 정해진 순서로 검사한다.
- `web/tests/playback-session.spec.ts`: 실제 모듈에 제어 가능한 로딩 결과와 브라우저 시계를
  연결해 지연·실패·해제 이후의 결과·움직임 설정·bfcache를 검사한다.
- 기존 웹 회귀 검사는 프로덕션 빌드의 Rive 파일로 DOM·접근성·연주 연결을 확인한다.
  Rive 소스를 바꾸면 [배포 절차](deployment.md#rive를-수정했을-때)에 따라 서명 파일을
  먼저 반영하고 실행한다. 소스 단위 검사만으로 새 서명 파일의 웹 동작을 검증했다고 간주하지 않는다.
