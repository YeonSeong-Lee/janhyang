# 활로 켜기

2026-11-17 재설계. 사용자가 그린 현과 수면은 유지하고, 활의 조작·음향·피드백을
하나의 연주 경험으로 연결했다. 실제 바이올린 녹음이나 특정 악기를 그대로 재현하는
제품은 아니다. 자유롭게 만든 현을 활로 연주하는 악기다.

## 연주 흐름

1. **활로 켜기**를 켠다. 현이 없다면 **연습 현 놓기**로 G3·D4·A4·E5의 네 현을
   만든다. 기존 현이 있으면 이 동작은 숨겨지며, 엔진에서도 추가 생성을 막는다.
2. 현 위에 활을 대고 누른다. 기본은 한 현 연주다. 누를 때 가장 가까운 현과 활 방향을
   고정한다. 다른 현으로 옮기려면 놓았다가 다시 누른다. **함께 켜기**는 활에 닿는
   모든 현을 울린다.
3. 활의 긴 방향으로 왕복한다. 그 방향의 이동 성분만 마찰에 에너지를 공급한다.
   현을 따라 옮기는 동작은 접촉 위치를 바꾼다. 빠른 입력 사이의 경로도 검사한다.
4. 압력 슬라이더로 마찰 반응을 조절한다. 마우스와 터치는 슬라이더를 쓰고,
   펜 입력은 접촉 중 실제 `PointerEvent.pressure`로 덮어쓴다. 펜을 놓으면 설정한
   압력으로 돌아온다. 압력은 음량만 키우는 값이 아니며 속도와 함께 발음을 바꾼다.
5. 멈추거나 놓으면 소리가 잦아든다. 일시정지, Esc, 포커스 이탈, 포인터 취소,
   모드·현 선택·합주 설정 변경도 진행 중인 활을 끝낸다.

화면의 밝은 접촉점, 활 끝의 손잡이, 현의 진동, 파문, 강도 막대와 상태 문구가
연주에 반응한다. 이동 방향 표시는 활의 로컬 방향을 기준으로 한다. 현의 배음은
끝에 가까운 곳과 가운데에서 다르다. 표시되는 음 이름은 선택한 현의 조율이며
여러 현을 함께 켤 때의 모든 음을 나타내는 것은 아니다.

**한 활 연주**는 선택한 현에서 1.25초 동안 활을 움직이는 대체 조작이다. 종료 시간은
물리 계산의 프레임당 시간 제한과 분리해, 느린 렌더러에서도 누적 경과 시간으로 끝낸다. 이전·다음
현 선택과 압력 조절까지 네이티브 버튼과 슬라이더로 사용할 수 있다. 버튼을 다시
누르면 새 한 활을 시작한다. Esc로 중단할 수 있고 포인터로 누르면 직접 연주로
넘어간다. 연습 현 생성 후 키보드 포커스는 한 활 연주 버튼으로 이어진다.
첫 이동·음향 명령·연주 상태는 버튼 명령을 처리할 때 함께 갱신한다. 다음 렌더 프레임이
연주 길이보다 늦게 와도 시작이 생략되지 않는다.

## 설계 방향

- 주인공은 수면과 직접 움직이는 활이다. 제어부는 활 모드에서만 나타나는 작은
  연주 패널로 모았다. 흑청색 수면 `#05070b`, 패널 `#101827`, 본문 `#e7edf9`,
  보조 글자 `#aab8d0`, 연주 피드백 `#c3cdfb`, 테두리 `#3d4d67`을 사용한다.
  나무색은 실제 활에만 쓴다.
- 한국어는 시스템 서체를 유지한다. 패널 제목 16px, 조작부 13–15px, 부연 12px로
  구분하고, 숫자 음 이름은 같은 폭 숫자를 사용한다. 불필요한 장식·자동 애니메이션을
  추가하지 않는다.
- 세로 화면은 수면 아래 중앙에 제어부를 두고, 높이가 낮은 가로 화면에서는 오른쪽에
  둔다. 연습 현은 초기 배치 시 제어부를 피한다. 사용자가 그린 현의 위치는 리사이즈로
  바꾸지 않으며, 현을 추가로 그릴 때는 활 모드를 끈다.
- 작은 화면에서 한 번에 네 현이 울리는 문제를 피하기 위해 기본은 한 현 연주로
  정했다. 합주를 원하는 사람만 명시적으로 함께 켜기를 사용한다.

## 음향과 화면의 연결

`bow.as`는 활 방향의 부호 있는 속도, 압력, 교차점과 접촉 현을 계산한다.
`main.as`는 약 60Hz로 각 현의 주파수·속도·압력·접촉 위치·믹스 음량을 오디오
스레드에 전달한다. 화면의 현은 기존 파동 방정식을 유지하고, 활의 이동 방향에
따른 느린 붙음·미끄러짐 모양으로 구동한다. 화면 진동은 소리를 관찰하기 위한
느린 표현이며 오디오 샘플을 그대로 그린 것은 아니다.

`bowed.as`는 접촉점에서 양 끝으로 전파되는 두 지연선과 속도 의존 마찰을 계산한다.
브리지 손실, 고주파 감쇠, DC 제거를 적용한다. 새 녹음 파일이나 외부 음원을
추가하지 않는다. 주파수가 바뀌어 음성 슬롯이 재사용되면 이전 지연선 내용을 비운다.
일반적인 튕기기 소리는 기존 모델을 유지한다.

- 부드러운 시작·종료와 방향 전환. 입력이 멈추면 에너지 공급도 멈춘다.
- 마지막 오디오 갱신 후 150ms가 지나면 목표 속도를 0으로 바꾼다.
- 합주에서는 현 개수의 제곱근으로 음량을 보정한다.
- 내부 파동을 제한하고, 합산 출력이 0.8을 넘을 때만 부드러운 제한기를 적용한다.
- 이는 간략한 물리 모델이며 실측 바이올린 몸체 공명이나 활털·송진의 모든 특성을
  재현하지 않는다. 음색의 선호도는 청취 평가가 필요하다.

## 연결 계약

`scene.rml`의 기존 속성·ID를 유지하고 아래 항목을 추가했다.

| 속성 | 용도 |
|---|---|
| `bowPressure` | 기본 또는 펜 압력, 0–1 |
| `bowLevel` | 화면 피드백용 연주 강도, 0–1 |
| `bowDirection` | 활 방향, -1 또는 1 |
| `bowPolyphonic` | 한 현 / 여러 현 연주 |
| `practiceStrings` | 빈 화면에 연습 현 생성 trigger |
| `bowStroke` | 선택한 현에서 한 활 연주 trigger |

`bowMode`, `cursor`, `cancelGesture`, `bowContacts`와 버튼 연주 속성도 계속 사용한다.
소스를 변경하면 [배포 문서](deployment.md)의 로컬 서명 빌드로
`web/public/janhyang.riv`까지 갱신해야 한다. CLI 캡처는 `rive/build`의 파일을 디버그
빌드로 덮어쓸 수 있으므로, 캡처 결과를 서명된 public 파일에 복사하지 않는다.

## 참고 자료

- [Paul Wintz, The Physics of a Bowed String](https://paulwintz.com/tools/bowed_string/):
  활의 힘·속도·접촉 위치를 따로 조절하는 시뮬레이터, 붙음과 미끄러짐의 설명.
- [STK Bowed](https://github.com/thestk/stk/blob/master/include/Bowed.h),
  [BowTable](https://github.com/thestk/stk/blob/master/include/BowTable.h):
  파동 전달과 비선형 마찰 접합의 참고 모델. 현재 코드는 이 구조를 바탕으로 프로젝트의
  오디오 처리·입력 수명·출력 제한에 맞춰 작성했으며 STK를 의존성으로 추가하지 않았다.

## 검증 기록

- `rtk proxy rive rive --test`: 30개 통과. 느린 프레임의 한 활 종료, 한 현 고정·합주, 이동 방향 분리,
  속도·압력 반응, 접촉 위치에 따른 파형 변화, 양방향 연주, 빠른 이동의 접촉,
  44.1/48/96kHz의 출력 안정성, 명시적 해제와 입력 시간 초과를 검사했다.
- `rtk proxy pnpm test` (`web`): 타입 검사·프로덕션 빌드와 Chromium 27개 검사 통과.
  기존 그리기·튕기기·로딩·격리·움직임 줄이기 회귀 검사도 포함한다.
- 렌더 프레임 간격을 1.5초로 늦춘 브라우저 회귀 검사에서 한 활의 시작·종료를 확인했다.
- 실제 Rive 파일과 연결한 키보드 연주·압력·현 선택·중단, 모바일 터치 에뮬레이션의
  다중 접촉·보조 손가락 해제·포인터 취소를 검사했다.
- 1280×800, 360×740, 740×360에서 캡처로 구성과 입력 공간을 확인하고 axe 위반
  0건, 가로 넘침 없음, 주요 제어부 44px 높이를 확인했다.
- 직접 그린 현을 왕복하는 입력 시퀀스를 48kHz float WAV로 렌더링했다.
  유효한 음성 출력, 제한 범위 내 피크, 마지막 0.5초 완전 무음을 확인했다.
  한 E3 시퀀스의 기본음도 목표 주파수 근처에 있는지 확인했다. 모든 조합의
  조율 정확도를 보장하는 검사는 아니다.
- 로컬 서명 빌드를 `web/public/janhyang.riv`에 반영했고 최종 `dist`와 해시가 같다.
  기존 Rive 런타임 청크의 500kB 경고는 남아 있다.

실제 iOS Safari·Android 기기의 첫 소리와 지연, 실제 펜 압력, 스크린 리더의
연주 사용성, 음색 청취 평가는 별도 수동 검증 대상이다. 터치 에뮬레이션이나
수치 음향 검사를 실제 기기·청취 평가로 간주하지 않는다.
